# ElevenLabs Signed URL Setup Guide

Following the official guide: https://elevenlabs.io/docs/agents-platform/customization/authentication#using-signed-urls

## Overview

Bobby now uses **Signed URLs** for secure, server-side authentication with ElevenLabs agents. This approach ensures your API key is never exposed to the client.

## How It Works

```
1. Client initiates conversation request
   ↓
2. Client calls /api/get-signed-url endpoint
   ↓
3. Backend receives request (origin validated)
   ↓
4. Backend calls ElevenLabs API with API key (secret)
   ↓
5. ElevenLabs returns short-lived signed URL (valid 15 minutes)
   ↓
6. Backend returns signed URL to client
   ↓
7. Client uses signed URL to connect to agent
   ↓
8. WebSocket connection established with agent
```

## Setup Instructions

### 1. Create ElevenLabs API Key

1. Go to [ElevenLabs Dashboard](https://elevenlabs.io/dashboard)
2. Navigate to **Developer → API Keys**
3. Click **Create API Key**
4. Set name: `Bobby Production` (or your app name)
5. Configure permissions:
   - ✅ Enable: **Conversational AI**
   - ✅ Scope: **Read agents**
6. Optional: Set credit limit (e.g., 100,000 credits/month)
7. Copy the API key

### 2. Get Your Agent ID

1. Go to **Agents** section in dashboard
2. Select your agent (create one if needed)
3. Click the agent ID to copy it
4. Keep it safe

### 3. Configure Environment Variables

Create or update `.env.local`:

```env
# ===== SERVER-SIDE (SECURE) =====
# Keep these SECRET - never commit or expose
ELEVENLABS_API_KEY=sk_your_api_key_here
ELEVENLABS_AGENT_ID=your_agent_id_here

# ===== CLIENT-SIDE (SAFE) =====
NEXT_PUBLIC_ELEVENLABS_AGENT_ID=your_agent_id_here

# ===== SECURITY =====
# Allowed origins for signed URL requests (comma-separated)
# Only these domains can request signed URLs
ALLOWED_ORIGINS=http://localhost:3000,https://app.example.com

# Node environment
NODE_ENV=development
```

### 4. Enable Authentication in Dashboard

1. Go to **Agents**
2. Select your agent
3. Click **Settings**
4. Under **Security** → **Authentication**
5. Enable authentication (optional - for added security)
6. Save

## Security Features

✅ **API Key Protection**
- Stored server-side in environment variables
- Never transmitted to client
- Never logged (except in server logs)

✅ **Signed URL Validation**
- Generated by ElevenLabs backend
- Valid for 15 minutes only
- Can only be used once
- Expires if not used within 15 minutes

✅ **Origin Validation**
- Server checks request origin
- Only whitelisted domains can request signed URLs
- Prevents abuse from other domains

✅ **Token Isolation**
- Each conversation gets a new signed URL
- Tokens are short-lived
- Can't be reused after expiration

## Troubleshooting

### "Origin not allowed"

**Issue**: Client gets 403 error
**Solution**:
1. Check `ALLOWED_ORIGINS` env variable
2. Verify your app domain is in the list
3. Ensure no typos
4. Restart the server

Example:
```env
# WRONG ❌
ALLOWED_ORIGINS=https://app.example.com

# CORRECT ✅ (including localhost for dev)
ALLOWED_ORIGINS=http://localhost:3000,https://app.example.com
```

### "ElevenLabs API key not configured"

**Issue**: Server can't generate signed URL
**Solution**:
1. Verify `ELEVENLABS_API_KEY` is set
2. Check it's not expired
3. Restart the server after setting env vars
4. Check logs: `node server.log`

### "No signed URL in response"

**Issue**: ElevenLabs API returns unexpected format
**Solution**:
1. Verify agent ID is correct
2. Check API key has required permissions
3. Check ElevenLabs API status
4. Check server logs for full error

### Signed URL Expired

**Issue**: WebSocket connection fails after 15 minutes
**Solution**:
- Expected behavior - designed this way for security
- App automatically requests new URL when needed
- Users can start new conversations

### "Failed to get signed URL" on Client

**Issue**: Frontend can't reach backend endpoint
**Solution**:
1. Check backend is running
2. Verify `/api/get-signed-url` route exists
3. Check network tab in browser DevTools
4. Check CORS headers (should be set)
5. Check backend logs

## API Reference

### GET Signed URL (ElevenLabs API)

Official reference: https://elevenlabs.io/docs/agents-platform/api-reference/conversations/get-signed-url

```bash
curl -X GET "https://api.elevenlabs.io/v1/convai/conversation/get-signed-url?agent_id=YOUR_AGENT_ID" \
  -H "xi-api-key: YOUR_API_KEY"
```

**Response:**
```json
{
  "signed_url": "wss://api.elevenlabs.io/v1/convai/conversation?agent_id=...&conversation_signature=..."
}
```

**Valid for**: 15 minutes

## Best Practices

✅ **DO**:
- ✅ Rotate API keys quarterly
- ✅ Use separate keys for dev/staging/prod
- ✅ Monitor signed URL generation
- ✅ Set credit limits on API keys
- ✅ Validate origins strictly
- ✅ Log all authentication attempts

❌ **DON'T**:
- ❌ Commit `.env.local` to git
- ❌ Use the same API key for multiple apps
- ❌ Expose API key in frontend code
- ❌ Use `NEXT_PUBLIC_` for secrets
- ❌ Skip origin validation
- ❌ Hardcode allowed domains

## FAQ

**Q: Can I use the same signed URL for multiple users?**
A: Not recommended. Generate a new signed URL for each session.

**Q: What happens if the signed URL expires during a conversation?**
A: The active WebSocket connection won't be closed, but you can't create new connections with expired URLs.

**Q: How many signed URLs can I generate?**
A: No limit, but consider rate limiting to prevent abuse.

**Q: Is my API key safe?**
A: Yes! It's stored server-side and never sent to the client.

**Q: Can I use this in a mobile app?**
A: Yes! That's one of the main benefits of signed URLs.
